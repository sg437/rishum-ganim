# תוכנית בנייה — לשונית "צהרון" בתיקי התלמידות

מסמך תכנון לפני הבנייה. מטרתו להסכים על המודל, המסכים והחישוב —
ורק אחר כך לכתוב קוד.

> **הרקע:** שיבוץ הצוות בצהרונים כבר קיים (הקשר שיבוץ `tzaharon` במסך
> "שיבוץ צוות", ומינימום לצהרון בהגדרות). מה שחסר הוא **הצד של התלמידות**:
> מי נרשמה, לאיזה גן, כמה קבוצות אפשר לפתוח מזה, וכמה כבר נפתחו.

---

## 1. ההחלטות שנסגרו

| נושא | ההחלטה |
|---|---|
| גודל קבוצה | **מינימום + מקסימום**, שניהם בהגדרות. גן שעבר את המקסימום מציע פיצול לשתי קבוצות, והמונה מחשב לפי זה. |
| צירוף גנים | **כמה שצריך, מאותו קמפוס.** בלי תקרה על מספר הגנים — רק חובה שכולם באותו קמפוס. |
| יחידת השיבוץ | **קבוצה, ורק אחרי שנפתחה.** במסך "שיבוץ צוות" → "צהרונים" יופיעו קבוצות פתוחות בלבד, לא גנים. |
| ייבוא רשימה | **סנכרון מלא, עם אישור.** תצוגה מקדימה מראה גם את מי שיורדת מהרישום, והביטול דורש אישור מפורש. |
| גילים בקבוצה | **מותר לצרף כמה גילים**, כל עוד זה אותו קמפוס. אין הגבלה. |
| חינוך | **אסור לצרף רגיל עם חינוך מיוחד**, והמינימום והמקסימום **נפרדים לכל סוג חינוך** — בכל אחד המספרים שונים. |
| תשלום צהרון | השדה כבר קיים במודל. **נכנס כאופציה כבויה** — התשלום מנוהל במשרד הראשי, ולכן העמודה מוצגת רק אם מדליקים אותה בהגדרות. |

## 2. מודל הנתונים

### 2.1 הגדרות — מינימום ומקסימום, בנפרד לכל סוג חינוך

המספרים שונים בין חינוך רגיל לחינוך מיוחד, ולכן ההגדרה אינה שדה אחד אלא
טבלה קטנה — שורה לכל סוג חינוך מתוך `EDU_TYPES`:

```js
DB.settings.tzaharonLimits = {
  "רגיל": { min:15, max:25 },
  'ח"מ' : { min:8,  max:14 }
}
```

**קריאה תמיד דרך פונקציה אחת**, שיודעת גם ליפול אחורה להגדרה הישנה:

```js
function tzLimits(edu){            // edu = "רגיל" / 'ח"מ'
  const L = (DB.settings.tzaharonLimits||{})[edu||"רגיל"] || {};
  return { min:+L.min || +DB.settings.tzaharonMin || 0,   // תאימות אחורה
           max:+L.max || +DB.settings.tzaharonMax || 0 }; // 0 = בלי תקרה
}
```

כך `tzaharonMin` הקיים ממשיך לעבוד עד שממלאים את הטבלה — בלי מיגרציה
ובלי רגע שבו המספר נעלם מהמסך. ההגדרה נכתבת מעכשיו רק לטבלה החדשה.

מקטע ההגדרות משנה שם מ"מינימום לפתיחת צהרון" ל**"צהרון — מינימום ומקסימום"**,
ובמקום שדה אחד מציג טבלה של שתי שורות בשתי עמודות. הוא נבנה מ-`EDU_TYPES`,
כך שאם יתווסף סוג חינוך שלישי הוא יופיע שם מעצמו.

### 2.2 קבוצות הצהרון — מבנה חדש

```js
DB.tzGroups = {
  'תשפ"ז': [
    { id:"tz_ab12cd",         // מזהה קבוצה. תמיד בתחילית tz_ — לא מתבלבל עם מזהה גן
      name:"רשב\"ם — גיל 3+4", // שם הקבוצה (ברירת מחדל נגזרת מהקמפוס והגנים)
      campus:"רשב\"ם",         // הקמפוס. בקבוצה חד-גנית — הקמפוס של אותו גן
      ganIds:["g1","g2"],      // גן אחד = קבוצה רגילה · כמה גנים = קבוצה מצורפת
      education:"רגיל",        // נגזר מהגנים, לצורך בורר החינוך
      status:"open",           // "planned" (צירוף שהוגדר) · "open" (נפתחה)
      openedAt:"2026-08-30T…", openedBy:"sg@…",
      legacyGanId:"g1",        // רק בקבוצות שנוצרו במיגרציה (ראה 6.2)
      note:"" }
  ]
}
```

**כללים:**
- גן יכול להיות **בקבוצה אחת בלבד** באותה שנה. נאכף בקוד ובבדיקות.
- קבוצה מצורפת — **כל הגנים באותו קמפוס ובאותו סוג חינוך**. הבורר בחלון הפתיחה מסנן לפי שניהם, ולכן צירוף אסור פשוט אינו מוצע.
- **גילים — בלי הגבלה.** גן גיל 3 וגן גיל 4 באותו קמפוס הם צירוף חוקי לגמרי. הגילים שהקבוצה מכסה מוצגים על הכרטיס שלה, כמידע ולא כמחסום.
- קבוצה **נמחקת** רק אם אין לה שיבוץ צוות; אחרת מוצעת "סגירה" (`status` חוזר ל-`planned`, השיבוץ נשמר).
- קבוצה עם `status:"planned"` נספרת ב"ניתן לפתוח", לא ב"נפתחו".

### 2.3 היכן זה נשמר

`tzGroups` נכנס למסמך ה-meta לצד `assignments` — נתון קטן, נכתב בכל שמירה:

- `metaForWrite()` — להוסיף `tzGroups: DB.tzGroups`
- קורא ה-meta (ליד `DB.assignments = meta.assignments||{}`) — להוסיף `DB.tzGroups = meta.tzGroups||{}`
- `blankDB()` — להוסיף `tzGroups: {}`

**רישום התלמידה עצמו לא משתנה** — הוא נשאר `s.programs.tzaharon`, בדיוק כמו היום.
הקבוצה נגזרת מהגן של התלמידה, ולכן אין כפילות ואין מה לסנכרן.

### 2.4 תשלום צהרון — אופציה כבויה

השדה `s.programsPaid.tzaharon` כבר קיים במודל ובעדכון הקבוצתי. התשלום עצמו
מנוהל במשרד הראשי ולא אצלנו, ולכן הוא נכנס כ**מתג בהגדרות**:

```js
DB.settings.tzaharonShowPaid   // ברירת מחדל: כבוי
```

כשהוא כבוי — שום דבר לא משתנה במסך. כשמדליקים אותו, נוספים שלושה דברים
ומיד: עמודת "תשלום" ברשימת הנרשמות, כרטיס "שילמו / לא שילמו" בשורת
הכרטיסים, וסינון לפי תשלום. אפס עלות כשלא משתמשים, ומוכן ליום שכן.

## 3. החישוב — "כמה קבוצות ניתן לפתוח"

זה הלב. הפונקציה `tzPlan()` מחזירה את כל התמונה במקום אחד, וכל הכרטיסים,
הטבלאות וההצעות ניזונים ממנה — כדי שלא יהיו שני חישובים שסותרים זה את זה.

**קלט:** הגנים בסינון החינוך הפעיל · מספר הנרשמות בכל גן · הקבוצות הקיימות ·
ולכל גן, `M` ו-`X` **של סוג החינוך שלו** — `tzLimits(eduLabel(gan))`. אין מספר
מינימום אחד למערכת; יש אחד לכל סוג חינוך, והחישוב שואל אותו מחדש לכל גן.

**שלב א — מוציאים מהמשחק גנים שכבר בקבוצה.**
גן ששייך לקבוצה קיימת (`open` או `planned`) לא נספר שוב ב"ניתן לפתוח".

**שלב ב — גנים שעומדים בעצמם.**
לגן עם `c` נרשמות:

```js
groups = Math.min( Math.floor(c / M),  X ? Math.ceil(c / X) : Infinity )
```

| חינוך | נרשמות | M | X | תוצאה |
|---|---|---|---|---|
| רגיל | 40 | 15 | 25 | **2 קבוצות** (20+20) |
| רגיל | 28 | 15 | 25 | **1 קבוצה** + התראה "3 מעל המקסימום" |
| רגיל | 50 | 15 | 25 | **2 קבוצות** מלאות בדיוק |
| רגיל | 9  | 15 | 25 | 0 — עובר לשלב ג |
| ח"מ  | 9  | 8  | 14 | **1 קבוצה** — אותו מספר נרשמות, תוצאה הפוכה |

חריגה מהמקסימום (`groups * X < c`) מסומנת בהתראה כתומה ליד הגן — לא חוסמת.
השורה האחרונה בטבלה היא בדיוק הסיבה שההגדרה מופרדת: אותן 9 נרשמות הן
"מתחת למינימום" בחינוך רגיל ו"קבוצה שאפשר לפתוח" בחינוך מיוחד.

**שלב ג — צירוף בתוך הקמפוס.**
כל הגנים שנשארו מתחת למינימום, מקובצים לפי **קמפוס וסוג חינוך יחד** —
זהו מפתח הקיבוץ, ולכן צירוף בין רגיל לחינוך מיוחד לא ייווצר גם לא בטעות.
בכל קבוצה כזו הגנים ממוינים מהגדול לקטן ונצברים עד שהסכום מגיע ל-`M`
של אותו סוג חינוך — זו הצעת צירוף אחת. ממשיכים עם השארית.
האלגוריתם חמדני ומוצג במפורש ("גן א 9 + גן ב 8 = 17"), כדי שתמיד יהיה
ברור מאיפה הגיע המספר, ואפשר יהיה לשנות ידנית.

**שלב ד — מה שנשאר.**
גנים שגם אחרי הצירוף לא הגיעו למינימום. לכל אחד שני מספרים:
- **חסר לפתיחה עצמאית** = `M − c`
- **חסר בקמפוס** = `M −` סכום השארית בקמפוס (אם יש עוד גנים חסרים בקמפוס)

**פלט `tzPlan()`:**

```js
{ totalRegistered, opened, openableStandalone, openableMerged,
  openableTotal, belowMinGans:[…], mergeSuggestions:[…],
  overMaxGans:[…], byGan:{ [ganId]: {count, gap, groupId, state} } }
```

> **כלל כתיבה (מתוך `HANDOFF.md`):** יחסים נכתבים **בלי רווחים** — `17/15` ולא
> `17 / 15` — או בעטיפת `unicode-bidi:isolate`. אחרת המספרים מתהפכים על המסך.

## 4. הניווט — לשונית משנה תחת "תיקי התלמידות"

בדיוק המנגנון שכבר עובד ב"הגדרות": חץ ▾ לצד הלשונית, ומתחתיו רשימת מקטעים.
הקוד קיים (`nav-caret`, `subnav`, `setNavOpen`) — רק מוכלל לשתי לשוניות.

```
🎒 תיקי התלמידות  ▾
     └─ 🧡 צהרון   (142)
```

- `TABS` — הלשונית `students` מקבלת חץ, בדיוק כמו `settings`.
- מסך חדש `tzaharon` ב-`route()`. הוא **לא** ב-`TABS` — ולכן כשהוא פעיל,
  כפתור "תיקי התלמידות" מוצג כפעיל, והחץ פרוש.
- **המסך נפרד לגמרי מ-`viewStudents`** — הנתונים של הצהרון לא מופיעים על
  מסך התלמידות הרגיל, בדיוק כפי שביקשת. רק מי שנכנס ללשונית רואה אותם.
- מונה קטן על פריט התת-לשונית = מספר הנרשמות לצהרון בשנה הפעילה.
- מאוחר יותר אפשר להוסיף שם גם "קייטנות" — המבנה כבר יתמוך.

## 5. המסך — `viewTzaharon`

### 5.1 שורת הכרטיסים למעלה

| כרטיס | מה מציג | לחיצה |
|---|---|---|
| **נרשמות לצהרון** (ראשי, כהה) | סה"כ נרשמות בשנה הפעילה | מסננת לרשימת הנרשמות |
| **קבוצות שנפתחו** | מספר קבוצות `open` | גוללת לטבלת הקבוצות |
| **ניתן לפתוח עכשיו** | עצמאיות + מצורפות. שורת פירוט: "5 עצמאיות · 2 מצורפות" | גוללת להצעות |
| **גנים מתחת למינימום** | מספר גנים, אדום אם >0 | מסננת לגנים החסרים |
| **שילמו / לא שילמו** | רק כשהמתג בהגדרות דלוק (ראה 2.4) | מסננת לפי תשלום |

כשבורר החינוך על "הכל", הכרטיסים סוכמים את שני סוגי החינוך, ושורת הפירוט
מתחת למספר מפרקת אותם — "רגיל 3 · ח"מ 1" — כי המינימום שמאחורי כל אחד שונה.

מתחת לכרטיסים שורת מצב אחת: **"נפתחו 7 · ניתן לפתוח עוד 4 · סה"כ אפשריות 11"**.
זו השורה שעונה על "בכל רגע נתון לדעת כמה נפתח וכמה עוד אפשר" — היא מתעדכנת
ברגע שקבוצה נפתחת, בלי רענון.

אם לא הוגדר מינימום — רמז: "לחישוב מדויק, הגדר/י מינימום ומקסימום בהגדרות ←".

### 5.2 סינון

גן (ריבוי) · קמפוס · גיל · חינוך · **מצב רישום: נרשמה / לא נרשמה / הכל** ·
מצב גן: ניתן לפתוח / מתחת למינימום / כבר בקבוצה.
"מצב רישום" הוא מה שעונה על **"לפי סינון בכל גן מי נרשמה ומי לא"**.

### 5.3 שלושה מקטעים על המסך

**א. הקבוצות שנפתחו** — טבלה: שם · קמפוס · הגנים שבה · מספר ילדות (`38/15`) ·
צוות משובץ (מתוך `ganAsg`) · פעולות: עריכה · מעבר לשיבוץ הצוות · סגירה.

**ב. הצעות צירוף** — כרטיס לכל הצעה:
> **קמפוס רשב"ם** · גן גיל 3 (9) + גן גיל 4 (8) = **17** ✓ מעל המינימום
> `[✂️ שינוי הרכב]` `[✅ פתיחת קבוצה]`

**ג. הגנים** — טבלה: גן · קמפוס · גיל · נרשמות (`12/15`, ירוק/אדום) · חסר ·
מצב · פעולה. לחיצה על שורה פותחת מתחתיה את **רשימת התלמידות של אותו גן**,
עם ✓ ליד מי שנרשמה ו-✗ ליד מי שלא, וכפתור לסימון ישיר.

### 5.4 חלון "פתיחת קבוצה"

שם (ברירת מחדל אוטומטית) · קמפוס · בורר גנים (ריבוי, מסונן לקמפוס שנבחר,
גנים שכבר בקבוצה חסומים) · סכום חי "סה"כ 17 ילדות · מינימום 15 ✓".
מתחת למינימום — אזהרה ואישור מפורש ("לפתוח בכל זאת?"), לא חסימה.
מעל המקסימום — הצעה לפצל לשתי קבוצות. המינימום והמקסימום שמוצגים בחלון הם
תמיד אלה של סוג החינוך של הקבוצה, וכתובים במפורש: "מינימום לחינוך רגיל: 15".

### 5.5 ייצוא

כפתור ייצוא/הדפסה — רשימת הקבוצות, טבלת הגנים ורשימת הנרשמות לפי הסינון הפעיל.

## 6. ייבוא הנרשמות מהמשרד הראשי

### 6.1 החלון

**מקור:** קובץ CSV / הדבקה מאקסל / **רשימת ת"ז נטו, מספר בשורה** —
שלוש הדרכים באותו שדה, זיהוי אוטומטי. קוד ההתאמה לפי ת"ז כבר קיים
(`muniSectionHTML` ו"עדכון לפי ת"ז") ויעשה בו שימוש חוזר, בלי עותק שני.

**תצוגה מקדימה** — ארבע קבוצות, כל אחת נפתחת לרשימה:

| | |
|---|---|
| ✅ **חדשות לרישום** | נמצאו במערכת, ייסומנו כרשומות |
| ⏺️ **כבר רשומות** | לא ישתנה דבר |
| ❓ **לא נמצאו** | ת"ז שאין לה תיק בשנה הפעילה — עם הרשימה להעתקה |
| ⚠️ **יורדות מהרישום** | רשומות היום ואינן ברשימה החדשה — **רק במצב סנכרון מלא** |

**מצב סנכרון מלא** — תיבת סימון "הרשימה מלאה — בטל רישום למי שאינה בה",
**כבויה כברירת מחדל**. כשהיא דלוקה, כפתור האישור אומר במפורש
"ייבוא וסנכרון · מבטל 12 רישומים", והרשימה של ה-12 פרושה מעליו.

**ביטול ייבוא אחרון** — כמו בייבוא התלמידות הקיים: המצב הקודם של כל תיק
שנגע בו נשמר, ולחיצה אחת מחזירה אותו.

### 6.2 מיגרציה של שיבוצי צהרון קיימים

שיבוצי `assignments[year].tzaharon` מפתוחים היום לפי `ganId`. במיגרציה
חד-פעמית, לכל גן כזה נוצרת קבוצה חד-גנית `{id:"tz_…", ganIds:[ganId],
status:"open", legacyGanId:ganId}`, והשיבוץ עובר למפתח החדש.
המיגרציה רצה בטעינה (`migrateTzGroups()`, לצד `migrateAssignments()`),
מזוהה לפי מפתח שאינו מתחיל ב-`tz_`, ואידמפוטנטית — הרצה שנייה לא עושה כלום.
`legacyGanId` נשמר כדי שתמיד אפשר יהיה להתחקות אחורה.

## 7. שיבוץ הצוות — מה משתנה

במסך "שיבוץ צוות", כשההקשר הוא **צהרונים**:

- טבלת הבחירה מציגה **קבוצות פתוחות**, לא גנים. עמודות: שם הקבוצה · קמפוס ·
  הגנים שבה · מספר ילדות · מצב שיבוץ.
- **קבוצה מצורפת = שיבוץ אחד.** אין יותר סיכוי לשבץ פעמיים את אותו צוות
  לשני גנים שהם באמת אותו צהרון — זה בדיוק מה שהמבנה החדש מונע.
- קבוצה שלא נפתחה **אינה מופיעה כלל** במסך השיבוץ.
- שורת הסיכום שם משתנה ל"קבוצות פתוחות · משובצות · ממתינות לצוות",
  עם קישור "פתיחת קבוצות ←" למסך הצהרון.
- בורר החינוך שבראש התוכנה ממשיך לעבוד כרגיל וגם מסנן את הקבוצות.
- שאר ההקשרים (פעילות הגן, קייטנות) — **לא נוגעים בהם בכלל**.

## 9. בדיקות (`tests/tzaharon.test.cjs`)

באותה תבנית של `tests/ui.test.cjs` — `index.html` האמיתי, Firebase מדומה:

1. `tzPlan()` — כל חמש הדוגמאות מטבלת שלב ב', כולל השורה של החינוך המיוחד.
2. `tzLimits()` — מחזירה מספרים שונים לרגיל ולח"מ, ונופלת נכון ל-`tzaharonMin` הישן כשהטבלה ריקה.
3. הצעת צירוף — לא חוצה קמפוסים, **ולא חוצה סוגי חינוך**.
4. צירוף גנים בגילים שונים באותו קמפוס — **מותר**, ולא מסומן כשגיאה.
5. גן שכבר בקבוצה אינו נספר שוב ב"ניתן לפתוח".
6. פתיחת קבוצה — "נפתחו" עולה ב-1, "ניתן לפתוח" יורד ב-1, מיד.
7. ייבוא לפי ת"ז — מסמן, מדלג על קיימות, מדווח על לא-נמצאו.
8. סנכרון מלא — מבטל רישום רק אחרי אישור, והביטול מחזיר.
9. הקשר "צהרונים" בשיבוץ — מציג קבוצות פתוחות בלבד.
10. מיגרציה — שיבוץ ישן לפי `ganId` עובר לקבוצה, והרצה שנייה לא משכפלת.
11. מתג התשלום — כבוי, אין עמודה; דלוק, יש עמודה וכרטיס.
