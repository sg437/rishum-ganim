# ריבוי ערים והמרכזי — איך זה בנוי 🏙️

> שלב א׳ של "המערכת הגדולה": פתיחת תוכנת הרישום של מודיעין עילית לערים נוספות,
> משתמשים לפי עיר, והמרכזי (`management.html`) שרואה את כל הערים חי.
> עודכן: אלול תשפ"ו (ספטמבר 2026).

---

## 1. שני מוצרים, קוד אחד לכל עיר, נתונים משותפים

| | תוכנת העיר | המרכזי |
|---|---|---|
| קובץ | `index.html` (+ `ui-lab.css`, `ui-lab.js`) | `management.html` |
| מי משתמש | הרכז/ת, הקלדנית, מנהל/ת העיר | מחלקת הרישום במשרד הראשי |
| מה רואים | **עיר אחת** בכל רגע (הערים שהמשתמש/ת משויך/ת אליהן) | **כל הערים**, חי |
| עיצוב | "רשת הגנים" — כולו ב-`index.html` / `ui-lab.css` | "רקיע" — כולו בתוך `management.html` |
| כתיבה | כל נתוני העיר | המרשם המרכזי בלבד |

**כלל ההפרדה (התשובה לחשש שהעיצוב "מתערבב"):**

1. **קוד:** למרכזי ולתוכנת העיר אין קובץ עיצוב משותף. `management.html` **אינו טוען**
   את `ui-lab.css`/`ui-lab.js` (עד היום הוא טען אותם דרך `?ui=new`, וזה מה שגרם
   לעיצוב הערים "לזלוג" למרכזי — הוסר). שינוי עיצוב במרכזי נוגע רק ב-`management.html`;
   שינוי עיצוב בערים נוגע רק ב-`index.html`/`ui-lab.*`.
2. **ערים:** כל הערים מריצות את **אותו** `index.html`. שינוי אחד בקוד מגיע לכל הערים
   בבת אחת — זה בדיוק "המסונכרן עם המרכזי" שרוצים, בלי להחזיק עותק לכל עיר.
3. **נתונים:** הסנכרון בין הערים למרכזי הוא **דרך הענן בלבד** (Firestore), לא דרך קוד.
   המרכזי מאזין לאותם מסמכים שתוכנת העיר כותבת, ורואה כל שמירה תוך שניות.

## 2. מבנה הנתונים בענן

```
org/meta                        ← המרשם המרכזי (מי הערים, מי רואה מה)
  cities: [ {id, name, region, absorption, coordinator, phone, active, …} ]
  users:  { "email": { name, hq:true|false, cities:{ "<cityId>": "admin"|"edit"|"view" } } }

app/*                           ← עיר הבית: מודיעין עילית — האוסף המקורי, לא הוזז
cities/<cityId>/app/*           ← כל עיר נוספת, באותו מבנה בדיוק:
  meta · gans · staff · management · branding · students_<שנה> · presence_<מייל>
```

* **עיר הבית** (`HOME_CITY`, מזהה `modiin-illit`) ממשיכה לחיות ב-`app` — **אפס הגירה**
  לנתונים הקיימים, וכל הבדיקות והקוד הישן ממשיכים לעבוד.
* כל הקוד שכותב/קורא מסמך של עיר עובר דרך `cityDoc()` / `cityColl()` / `cityRestBase()`
  (ב-`index.html`). הפונקציות האלה הן הנקודה היחידה שיודעת איפה העיר יושבת.
* מזהה עיר: אנגלית, אותיות קטנות, ספרות ומקפים (למשל `beitar-illit`). נקבע פעם אחת
  ואינו משתנה — הוא שם האוסף בענן. השם העברי ניתן לשינוי.

## 3. מודל ההרשאות

| מי | רואה | מוגדר איפה |
|---|---|---|
| **בעלי המערכת** (`OWNER_EMAILS`) | הכל, תמיד | קבוע בקוד (index.html, rules, Apps Script) |
| **מרכז** (`hq:true`) | כל הערים + המרשם | המרשם המרכזי |
| **מנהל/ת עיר** (`admin`) | העיר שלו/ה — כמנהל/ת מערכת בה | המרשם המרכזי |
| **עריכה** (`edit`) | העיר שלו/ה — עבודה רגילה | המרשם המרכזי (+ צמצום לחינוך רגיל/מיוחד ב"ניהול משתמשים" של העיר) |
| **צפייה בלבד** (`view`) | העיר שלו/ה — בלי שינויים | המרשם המרכזי |
| **משתמש/ת ותיק/ה** (לא במרשם) | עיר הבית בלבד, לפי רשימת המורשים של העיר | `settings.allowedEmails` וכו׳ — כמו עד היום |

* משתמש/ת יכול/ה להיות משויך/ת ל**כמה ערים** עם תפקיד שונה בכל אחת (למשל מנהל/ת
  במודיעין עילית וצופה בירושלים). בכניסה — מסך בחירת עיר; אחר כך אפשר להחליף מהתפריט.
* משתמש/ת שמשויך/ת רק למודיעין עילית **אינו/ה רואה ירושלים** — לא בבורר, לא בנתונים,
  וגם לא בעקיפת המסך: כללי השרת (`firestore.rules`) חוסמים קריאה וכתיבה של אוסף עיר אחרת.
* "תלמידי חוץ" (ילדים מעיר אחרת בגן של מודיעין עילית) שייכים לעיר **שבה הגן** —
  ההרשאה היא לפי מיקום הגנים, לא לפי כתובת הילד/ה.
* למרכזי נכנסים רק **בעלים ומרכז**. משתמש/ת עיר שינסה — יקבל הסבר ויופנה לתוכנת העיר.

### איפה זה נאכף
1. **בדפדפן** — `cityAccess()` / `myCities()` / `isAdmin()` / `myEditScope()` ב-`index.html`.
2. **בשרת** — `firestore.rules`: `org/meta`, `app/*`, `cities/{cityId}/app/*`.
3. **בגשר** — `APPS_SCRIPT.gs`: `allowedGate_` / `adminGate_` קוראים את המרשם ומקבלים
   `cityId` בכל בקשה; תיקיות ה-Drive של עיר נוספת נפתחות תחת `ערים/<שם העיר>/`.

## 4. איך פותחים עיר חדשה (למרכז)

1. נכנסים ל-`index.html` (כמרכז) → **הגדרות → ערים ומשתמשים (מרכזי)**,
   או ל-`management.html` → **הרשאות עבודה**. שני המסכים כותבים לאותו מרשם.
2. **פתיחת עיר:** שם עברי → המזהה באנגלית מתמלא לבד (אפשר לתקן) → אזור → אופן הקליטה
   (קליטה דיגיטלית בעיר / קליטה במשרד הראשי) → "פתיחת עיר".
3. **שיוך משתמשים:** אימייל Google → עיר → תפקיד. המשתמש/ת נכנס/ת ל-`index.html`
   עם חשבון Google ורואה רק את העיר שלו/ה. כתובת ישירה לעיר: `index.html?city=<מזהה>`.
4. בעיר החדשה: הגדרות → שנים, קמפוסים, גילים, רף שיבוץ — ומתחילים לרשום.
5. **ייבוא המורשים הקיימים:** בפאנל המרשם יש כפתור "ייבוא מורשי מודיעין עילית למרשם" —
   מעביר את כל מי שברשימת המורשים של העיר למרשם עם הרשאה לעיר הזאת בלבד
   (מנהלי המערכת → מנהל/ת עיר, צופה → צפייה, השאר → עריכה). לא חובה — בלי ייבוא הם
   ממשיכים לעבוד בדיוק כמו היום.

## 5. גני בנים וגני בנות, רישיון

* בכרטיס הגן נוסף **מגדר הגן** (בנות / בנים). הילד/ה יורש/ת את המגדר מהגן — לכן אין
  שדה מגדר בתיק, ויש סינון "מגדר (לפי הגן)" ברשימת התלמידים ובטבלת הגנים.
* **רישיון:** גילאים מורשים ומכסת ילדים לפי רישיון משרד החינוך. גן שחורג מהמכסה מסומן
  בכרטיס, בטבלת העיר במרכזי ("רישיון") ובמונה "חריגות רישיון" של העיר — לפי הצורך
  שתואר במסמך מחלקת הרישום (בקרת קליטה מול גיל הרישיון וטיפול בהרחבת רישיון).

## 6. מה המרכזי מציג חי (ומה עדיין הדמיה)

**חי, מהערים:** דף הבית (מונים), סקירה לאומית (מונים, טבלת ערים, פעילות חיה — כל שמירה
בתוכנת עיר מופיעה כאירוע), ערים וגנים (רשימת הגנים של כל עיר, וצלילה לגן: צוות משובץ,
תלמידי הגן, תוכניות), אחוזים ותפוסות (מלאות, מועדי רישום אמיתיים, אזורים), פעילויות
(צהרון/קייטנות מהתיקים), עובדות ושיבוץ (מאגרי הצוות), מערכת רישום (רשומים/משובצים/
ממתינים/קלוטים בעירייה, נרשמו היום, קישור לכל עיר), שיבוץ ילדים (הממתינים האמיתיים),
הרשאות עבודה (המרשם המרכזי — ערים ומשתמשים).

**אחרי כניסה — אפס הדמיה.** ברגע שמשתמש/ת מרכז נכנס/ת, כל מה שההדמיה ציירה נמחק
(פידים, ערים ועובדות מומצאות). מסכי ההדמיה (כרטיסי משפחה, פורטל, סליקה, מסמכים,
שעות ושכר, האפיון, התוכנית) **לא נמחקים** — הם עוברים לקבוצת תפריט "יופעל בהמשך",
מעומעמים, עם באנר בראש המסך, כדי שלא יתבלבלו עם הנתונים החיים. הנתונים מוצגים
**בתוך** המרכזי (אין קישורים החוצה לתוכנות הערים), וכל תקלה בקבלת נתוני עיר
מוצגת בראש המסך במקום להישאר שקטה.

**המודולים של מחלקת הרישום (ספטמבר 2026)** — כולם חיים, מופיעים רק אחרי כניסה:
תלמידים · כל הערים (כל התיקים, שיבוץ מרכזי, ייצוא לפי שדות) · עובדות ושיבוץ ·
ייבוא מאקסל לעיר · ערוצי רישום ואחראיות קליטה · הפצה ופרסום · מפת שיבוץ ארצית ·
הפצת שיבוץ · Smoove · פניות וערעורים · פילוחים ודוח להנהלה · דורש טיפול · רישיון
וסייעת ב׳ · בקרת משרד החינוך · חוזרי מנכ״ל · מרכז הודעות · החלטות · הגדרות והרשאות
(לפי משתמש/ת ומודול) · עוזר חכם · מדריך. פירוט: [`CENTRAL_GUIDE.md`](CENTRAL_GUIDE.md);
מפת הדרישות ומצב המימוש: [`CENTRAL_REQUIREMENTS.md`](CENTRAL_REQUIREMENTS.md);
אבטחה: [`SECURITY.md`](SECURITY.md).

**אחסון המרכזי בענן:** `org/hq` (הגדרות: ספים, הרשאות מודולים, אנשי קשר, ערוצים,
נוסח Smoove, מיילים חוזרים) ותת-אוספים `org/hq/{requests, decisions, flags,
circulars, campaigns, snapshots, tracking, ministry, audit, imports}`. קריאה
וכתיבה — מרכז ובעלים בלבד (`firestore.rules`). מה שהמרכזי משדר לעיר (שיבוץ
מרכזי, ייבוא) נכתב **לאוסף העיר עצמה**, בטרנזקציה, באותו מבנה דחוס שתוכנת העיר
כותבת — ולכן העיר רואה אותו חי ומיזוג-הכתיבה שלה שומר עליו.

**עיצוב:** המרכזי עבר לזהות "מגדלור" (כחול-עמוק / טורקיז / ענבר, ניווט עליון
בדסקטופ) — כולו בתוך `management.html`, בלי לגעת בערים.

בלי התחברות המרכזי מציג את שער הכניסה בלבד. `?demo=1` פותח את ההדמיה במפורש.

## 7. פריסה — מה צריך לעשות פעם אחת

1. **כללי השרת:** Firebase → Firestore → Rules → להדביק את `firestore.rules` → Publish.
   בלי זה עיר חדשה תיחסם בשרת (הכללים הישנים מכירים רק את `app`).
2. **הגשר:** להחליף את `Code.gs` ב-`APPS_SCRIPT.gs` המעודכן → Deploy → Manage deployments
   → New version (גרסת הגשר: `2026-09-02`). בלי זה תיקיות Drive של עיר חדשה ייפתחו
   בתיקיית הבית, ומשתמשי עיר חדשה יקבלו "not-allowed" מהגשר.
3. **המרכזי:** `management.html` באותו אתר. הדומיין כבר מאושר ב-Firebase Auth.
4. `OWNER_EMAILS` ומזהה עיר הבית חייבים להישאר זהים בארבעת המקומות:
   `index.html`, `management.html`, `firestore.rules`, `APPS_SCRIPT.gs`.

## 8. מה נשאר לשלבים הבאים

* **טופס הרישום להורים** (`register.html`) לפי עיר (`?city=`) — כרגע הטופס הציבורי כותב
  לעיר הבית דרך הגשר.
* **גיבוי אוטומטי יומי** בגשר (`backupFirestore_`) מגבה את `app` בלבד — להרחיב לאוספי הערים.
* **חיבור API ל-Smoove** ו**סנכרון נרשמים אוטומטי מנדרים פלוס** — היום מעקב ותיעוד
  במרכזי, והקבצים עוברים ידנית (ראה CENTRAL_REQUIREMENTS.md).
* **אכיפת הרשאות המודולים של המרכזי גם בשרת** (היום בממשק; בשרת — ברמת "מרכז").
* הרשאות **לפי גן** (ולא רק לפי עיר) — אם יידרש למשתמשי "קמפוס".
