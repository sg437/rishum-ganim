שלושה שירותי ענן, תפקיד אחד לכל אחד

כל האפליקציה היא קובץ אתר אחד שרץ בדפדפן — בלי שרת משלכם. במקום שרת, המערכת נשענת על שלושה שירותים חינמיים: GitHub מארח את האתר, Firebase שומר את הנתונים ומטפל בהתחברות, ו־Apps Script מגשר אל Google Drive וניהול המשתמשים.

GitHub

האירוח — "השרת" של האתר

מביא את האפליקציה אל המשתמש, ומחזיק את הקוד עצמו.

  • מפרסם את קובץ ה־HTML כאתר חי דרך GitHub Pages.
  • מגיש את האפליקציה לדפדפן — ותו לא.
  • לא שומר שום נתוני תלמידות; רק מגיש קוד.
  • כאן מנוהלים הקוד, הענפים והגרסאות.
Firebase

מסד הנתונים + ההתחברות

הלב של המערכת — מקור האמת של כל הנתונים.

  • Firestore — תיקי תלמידות, גנים, צוות, שיבוצים והגדרות. מסתנכרן בזמן אמת בין כל המכשירים.
  • Authentication — כניסה עם אימייל וסיסמה או חשבון Google; רק מי שהוגדר מראש.
  • כללי אבטחה (firestore.rules) מוודאים שרק משתמש מחובר קורא או כותב.
Apps Script

הגשר לחשבון Google של הארגון

מכסה מה ש־Firebase לבד לא עושה — רץ בחשבון הארגון כ־Web App.

  • Google Drive — תיקייה לכל ילדה ולכל איש צוות, העלאה, צפייה והורדה של מסמכים — בלי חיבור Google אישי לכל משתמש.
  • ניהול משתמשים — מנהל מוסיף, מאפס סיסמה ומוחק ישירות מתוך התוכנה.
  • שיקוף ל־Google Sheets — גיבוי ודוחות; מראה בלבד, מקור האמת נשאר Firestore.
  • כל בקשה מאומתת מול Firebase, כולל בדיקת הרשאת מנהל — לא ניתן לעקוף מהדפדפן.

איך בקשה אחת עוברת במערכת

מרגע שהמשתמש נכנס ועד שהמסמך נשמר — כל שירות נכנס בתורו.

  1. נכנסים לכתובת האתר GitHub Pages השרת מגיש את index.html לדפדפן.
  2. מתחברים Firebase Auth אימייל וסיסמה או חשבון Google; רק משתמש מורשה נכנס.
  3. קוראים וכותבים נתונים Firestore כל שינוי נשמר ומסתנכרן בזמן אמת בין כל המכשירים.
  4. מעלים מסמך או מנהלים משתמשים Apps Script האתר קורא לגשר, שפועל מול Google Drive ו־Firebase Auth בחשבון הארגון.
